# GPUI migration ledger

The record of the move of the desktop front end from Rune to GPUI Kit 0.9.1, as the plan asks for it
([GPUI-MIGRATION.md](GPUI-MIGRATION.md), "Ledger format"): what every command, scene and test of the Rune
front end became, which Rune defects the port corrected, and where the port differs from the plan or from
the Rune client. It replaces the ledger of the earlier phases, which described a preview shell that no
longer exists.

State at the commit this ledger was written for (branch `gpui-migration`, 2026-11-19): all 29 areas of the
Rune front end have a port in `crates/xenadmin-ui/src/areas/<id>/`, the shell and the one generic renderer
are in `crates/xenadmin-gpui`, and `crates/xenadmin-desktop` (the Rune front end) is frozen and still
compiles. The Rune binary is still the released artifact; the cutover (Phase 5) has not happened.

## What has been verified, and what has not

`AGENTS.md` asks that implemented, fixture-verified, live-host-verified and planned behaviour be reported
separately. For the GPUI front end, every status in this ledger means the following and nothing more.

| level | what it covers here |
| --- | --- |
| implemented | The 238 commands, the surfaces behind them and the 129 Rune scenes exist in the new crates |
| fixture-verified | Model tests of `xenadmin-ui` (945 test functions) and headless tests of `xenadmin-gpui` (107 test functions) on synthetic inventories; a few tests connect the real backend to the local fixture server (`xenadmin_ui::testing`). Every registered scene renders in the headless scene tool. "Headless" means a window that is never shown: no compositor, no pointer or keyboard device, no clipboard, no portal dialog, no screen reader |
| live-host-verified | Nothing. No part of the GPUI front end has been run against an XCP-ng host, in the lab or elsewhere. The live evidence under `docs/reports/` was recorded through the core facade or through the Rune client |
| verified in a real window | Nothing. The GPUI client has not been started in a Wayland or X11 session for this port. The only seat run is the spike of gate G0, whose open points are the accepted limits of [decision 0006](decisions/0006-console-key-codes.md), listed under Deviations |
| planned | The window halves of the tests marked below, the measurement of `large-inventory`, the live re-recording of the supported core, the cutover |

The test suites were not run again to write this ledger: the counts above are counts of test functions in
the tree (`scripts/gpui_ledger_tables.py check` prints them), and the last recorded runs are the
engineers' at their merges.

## How this ledger is generated and checked

Places are abbreviated: `ui:x` is `crates/xenadmin-ui/src/x`, `gpui:x` is `crates/xenadmin-gpui/x`.

```sh
# the registry, as the scene tool prints it (scripts/check.sh writes the same file)
cargo run -p xenadmin-gpui --features scenes --locked --quiet --bin xenadmin-scenes -- --commands > artifacts/gpui/commands.txt
# the whole ledger against the repository
python3 scripts/gpui_ledger_tables.py check --commands artifacts/gpui/commands.txt
```

| table | generated by | needs the Rune crate |
| --- | --- | --- |
| Commands | `scripts/gpui_commands_table.py`, every column | no |
| Scenes | `scripts/gpui_ledger_tables.py scenes`, every column | no (the 129 Rune names are kept in `ui:scene.rs`) |
| Tests | `scripts/gpui_ledger_tables.py tests` gives the Rune file, the test, its kind and the successors that carry its name; the disposition, the other successors and the note are written by hand | yes for the first three columns; `check` verifies the successors without it |
| Mirror fixes, Deviations | by hand, from the engineers' results and the headers of the areas | no |
| Appendix | `scripts/gpui_ledger_tables.py keys` gives the Rune file and the key; the rest is by hand | yes |

The Rune columns of the Tests table and the whole key list of the appendix were generated on 2026-11-19
while `crates/xenadmin-desktop` still existed. Once that crate is deleted they are a record: `check` then
still verifies the Commands table, the Scenes table, that every successor named in the Tests table is a
test function of the file it names, the counts, and that every table is well formed.

### Tests by disposition

| disposition | tests | meaning |
| --- | --- | --- |
| moved | 154 | a test that built no `rune::Runtime`, now a test of `xenadmin-ui` (or of the GPUI crate where its subject went) |
| ported | 198 | a test that drove a `rune::Runtime`, rewritten against the model (the `Harness` presses the keys of the description) or as a headless GPUI test |
| split | 11 | a model test and a headless window test in `crates/xenadmin-gpui/tests` |
| retired | 4 | no successor is wanted; the reason is in the row |
| open | 4 | no successor, or half of one, and no recorded reason |
| total | 371 |  |

Of the 371 Rune tests, 156 built no `rune::Runtime` (kind `pure`) and 215 drove one (kind
`runtime`). 171 of the runtime tests ran in a compact window (513x652, or 480 wide) alone or beside
1440x900. A model test has no window, so that a control stays inside the window at a size is asserted only
by the split rows and by the renderer's own tests. 63 ported rows carry the note "model half": by
its name the Rune test promised that controls stay reachable or visible at its window sizes, and no
window test for it is on this branch. The note was assigned from the name of the Rune test, not by
reading each body. The 4 open rows say in their note what is missing.
