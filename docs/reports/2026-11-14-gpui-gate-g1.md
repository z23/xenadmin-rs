# Gate G1

Result: **the shared model is in place and the Rune front end uses it.** Full `./scripts/check.sh` did not finish on this machine. Two unchanged `xenadmin-core` file-identity tests fail here because a rewritten file keeps the same device, inode, and timestamps. They are not part of this phase, and they passed in the GitHub `check` job on the Phase 0 commit. `xenadmin-core`, `xenadmin-xapi`, and `xenadmin-process` were not modified.

## What the Rune front end now uses

- `xenadmin_ui::demonstration` and `populate_demo_details` build the demo and large-inventory pools.
- `project_rows` and `compare_rows` build and order the inventory table. Name order is still Rune's natural comparison.
- `infrastructure_nodes` builds the pool, host, and guest tree.
- `memory_label` and `storage_bytes` are the labels the other desktop modules already called.
- The scene registry lists all 128 scene names. `demo`, `large-inventory`, `host-version-notice`, and `unavailable-actions` are marked ported because their inventory comes from the shared model. The views are still Rune.
- The tab matrix and the command table are tested in `xenadmin-ui`. Rune buttons are catalogued in the ledger and still dispatch themselves.

`cargo tree -p xenadmin-ui -e normal --locked` shows `xenadmin-core`, `serde`, and `uuid`. No `rune`, `rune-kit`, or `gpui` crate. `scripts/check.sh` now refuses that dependency.
