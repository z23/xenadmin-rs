# GPUI migration, gate G5 (cutover): state on 2026-11-19

Gate G5 of [the migration plan](../GPUI-MIGRATION.md) ("Phase 5: cutover"), criterion by criterion,
with the state of the six steps of the phase. Each criterion is quoted word for word from the plan and
is one of: **met**, **partly met** or **not met**, with what shows it and what is missing. There is no
earlier report for this gate.

**The gate is not passed.** Criterion 1 is met. Criteria 2 and 3 are not met: they need a packaged
build run in a real window and a CI run, and both are the operator's.

Terms as in [the G2 report](2026-11-19-gpui-gate-g2.md). Nothing of the GPUI front end has run in a
real window on a compositor.

## Criteria

### 1. "`./scripts/check.sh` passes and `cargo tree --workspace` shows no `rune` crate."

**Met.**

`./scripts/check.sh` was run twice on 2026-11-19 with no display (`DISPLAY` and `WAYLAND_DISPLAY`
unset, `XENADMIN_TEST_TIME_SCALE=4`), both times with exit status 0:

- by the cutover, at commit `581ba08`, the last commit of the code;
- for these reports, started at commit `c82bc7c` and finished with the tree at `b480717`. Between
  `581ba08` and the end of that run only documents, three pictures and
  `scripts/gpui_ledger_tables.py` changed, none of which the script builds; the Python tests of
  `lab/` and `packaging/`, its last steps but one, ran on the later tree.

In the second run: the model's tests 976 passed and 3 ignored; the front end's tests with the feature
`scenes` 221 passed and 14 ignored (the 13 live tests and the measurement); over the whole workspace
2,029 passed in the first test step and none failed anywhere; 141 scenes listed and 151 PNG files with
150 element trees written to `artifacts/ui/`; 32 tests of `lab/` and 26 of `packaging/` passed; the
last step found both executables, `xenadmin-rs` and `host-probe`, in the workspace build. The log is
not in the repository.

`cargo tree --workspace --locked` lists no crate named `rune` or `rune-kit` (the script fails if it
does, and the removal of the Rune crate took 71 packages out of `Cargo.lock` without changing the
version of any that remain).

What that run is and is not: formatting, Clippy with warnings denied, the workspace's tests, the tests
of the front end on the Kit's headless test platform, a render of every scene with the software or
hardware adapter of the development workstation, and the Python tests of `lab/` and `packaging/`. The
13 live tests are ignored in it. It was run on the development workstation (Arch); the changed
workflows have not run on Ubuntu 24.04, where the list of build packages is derived, not tried.

### 2. "The packaged recovery gate is repeated on the release artifact."

**Not met.**

There is no release artifact: no version has been chosen for the cutover release (decision D10 is
the operator's), no tag exists for it, and no AppImage of the GPUI front end has been built. The
recovery gate (with Xen Orchestra shut down, locate the XO VM, start it and use its console, from a
package on an empty state directory) was last recorded on 2026-11-11 with the 0.17.0 AppImage, which
carried the Rune interface.

It needs the release build and the operator's run in a real window on the lab.

### 3. "CI builds the archive and AppImage with complete notices."

**Not met.**

Nothing of the cutover has been pushed, so no CI run exists. Locally, at the cutover:
`./scripts/package.sh` (without `--appimage`, which downloads tools) built the archive with the
client, the host probe, 695 package notices and `third-party/licenses`; the notice collector now
supplies a standard licence text for a package that ships none and fails for a package with neither a
notice nor a standard licence (none today); the packaging tests pass. The AppImage was not built. The
workflows were edited to install the packages the new client links and were not run.

It needs a push by the operator and a look at the first run of both workflows.

## What the cutover leaves open

In the order in which it can be closed:

1. Push, and see CI build the archive and the AppImage (criterion 3).
2. A run of the packaged build in a real window on the lab, with the recovery gate (criterion 2, and
   criterion 1 of gate G3). It is also the first run of the client on a compositor: the Wayland key
   path of the console, the clipboard, the portal file chooser, activation by a second start,
   fullscreen and client-side decorations have been established on the test platform only.
3. The driven desktop session (gate G3, criterion 3) and the paths of gate G3, criterion 2, that the
   headless run left out.
4. The clean-install check on Arch and Ubuntu 24.04 (step 5).
5. A screen reader run, before the accessibility statement can change (decision D11).
6. The release: its version, its report, its tag, and the repository description on GitHub.
