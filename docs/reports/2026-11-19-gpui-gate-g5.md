# GPUI migration, gate G5 (cutover): state on 2026-11-19

Gate G5 of [the migration plan](../GPUI-MIGRATION.md) ("Phase 5: cutover"), criterion by criterion,
with the state of the six steps of the phase. Each criterion is quoted word for word from the plan and
is one of: **met**, **partly met** or **not met**, with what shows it and what is missing. There is no
earlier report for this gate.

**The gate is not passed: criterion 2 is partly met.** Criteria 1 and 3 are met. Of criterion 2, the
recovery gate was repeated with the AppImage CI built at commit `e808a2f`, in a virtual machine with
injected input and a software renderer; there is no release artifact to repeat it on, and the
release is the operator's. (Brought up to date later on 2026-11-19, after the runs of that day and
the merge of their branches.)

Terms as in [the G2 report](2026-11-19-gpui-gate-g2.md). The GPUI front end has run in windows only in
virtual machines, with software rendering and without a person
([clean installation](2026-11-19-gpui-clean-install.md), [driven session](2026-11-19-gpui-vm-session.md)).

### 2. "The packaged recovery gate is repeated on the release artifact."

**Partly met.**

Shown: the recovery gate (with Xen Orchestra shut down, locate the XO VM, start it and use its
console, from a package on an empty state directory) was repeated on 2026-11-19 with the AppImage of
the GPUI front end that CI built at commit `e808a2f`, in a virtual machine with injected input and a
software renderer ([session report](2026-11-19-gpui-vm-session.md), section E;
[the G3 report](2026-11-19-gpui-gate-g3.md), criterion 1, has the steps).

Missing: "the release artifact". There is none: no version has been chosen for the cutover release
(decision D10 is the operator's) and no tag exists for it. The AppImage of that run is a CI build of
a branch, and the fixes merged since are in no package (a second start that showed nothing, a held
key that did not repeat in a console, a start without a display or a font that did not end with a
plain message). The criterion's words are therefore not satisfied by that run, whatever the machine
it was made in.

It needs the release build, and the gate on it; a person at a desk with a hardware GPU is what that
repeat would add to the run in the virtual machine.

### 3. "CI builds the archive and AppImage with complete notices."

**Met**, for the pushed commit `e808a2f`.

The branch was pushed after the cutover, and run 44436396899 of `ci.yml` built
`xenadmin-rs-0.20.0-linux-x86_64.tar.gz` and `.AppImage` at commit `e808a2f` on Ubuntu 24.04. Two
engineers downloaded them; for this report their `.sha256` files were verified again and the archive
was opened: `third-party/dependencies.json` has 695 entries, with a directory of notices for each
package and `third-party/licenses` with the Apache-2.0, MIT and Zlib texts; the clean-install run
found the same tree in the AppImage, with the notices of the AppImage runtime added
([report](2026-11-19-gpui-clean-install.md), "The notices"). The notice collector supplies a standard
licence text for a package that ships none and fails for a package with neither a notice nor a
standard licence; the review of the cutover compared its 695 packages with the dependency trees of
the two shipped binaries and found none missing. The criterion's words are satisfied: CI built both
packages, and every package of the locked graph has its entry.

What "complete" rests on, for the operator to judge (general information, not legal advice): 35
packages of the locked graph, 27 of them in the trees of the two shipped binaries, declare MIT,
Apache-2.0 or Zlib and ship no licence file of their own; for these the archive carries the standard
text with the licence's placeholder in place of a copyright line, plus the authors and repository
from the package's manifest. Whether that meets each licence's notice terms is the owner's decision,
as `packaging/licenses/README.md` says.

Not shown: the release workflow (`release.yml`) has not run; a tag starts it. The tree as merged for
this report is not pushed, so CI has not built it. It adds no package to the locked graph (two that
were already locked became direct dependencies: `wayland-protocols` of the client, `rusqlite` of the
model's tests), and it adds a run of the packaged client by the check and by the packaging script
(`packaging/smoke.py`), which has not run on Ubuntu.

In the order in which it can be closed. Items 1, 3 and 4 of the list this report first had (a push
and a CI run, the driven session and the paths the first headless run left out, the clean-install
check) were done on 2026-11-19 as far as they can be without a person; what is left of them is
below.

1. Push the merged tree and see CI build its packages: the fixes of 2026-11-19 are in no package.
2. A person's run of a package in a real window on a desk, with a hardware GPU, on the operator's
   compositor, with the recovery gate (criterion 2, on the release artifact). The run in the virtual
   machine showed the Wayland key path of the console, the clipboard, the portal file chooser,
   activation by a second start, fullscreen and decorations on sway 1.12 with software rendering and
   injected input; it showed nothing on Hyprland, GNOME or KDE, nothing on X11 with a console, and no
   keyring.
3. The paths of gate G3, criterion 2, that are still missing: a coordinator change and maintenance of
   the coordinator through the front end, the host's own refusal of an evacuation, the keyring.
4. The operator's word on the 18 actions that stay outside a row of commands (gate G2, criterion 5).
5. A screen reader run by a person, before the accessibility statement can change (decision D11).
6. The release: its version, its report, its tag, and the repository description on GitHub.
