# Initial development alpha

This report accompanies the initial alpha implementation commit. It records local results,
not XCP-ng compatibility certification. No live host, production inventory, or credential
was used. No complete M0–M2 acceptance gate has passed.

## Build identity

- Application: workspace version 0.1.0, development alpha.
- Toolchain: Rust 1.99.1, `x86_64-unknown-linux-gnu`.
- Rune: `f3d04f3f2069d177d04c963b0ba9f6b2065e46eb`.
- RFB decoder: `vnc-rs` 0.6.0, candidate pending actual XCP-ng console qualification.
- Lockfile SHA-256: `65c550f516cea2a5023b14bf26e150af2c3fc6a03457b1b735be5d4587c8a0c6`.
- Workstation: Omarchy 4.0.0.r7602.gd5b32d2, Arch-derived, x86-64.
- Renderer used for local images and native presentation: NVIDIA GeForce RTX 5090 Laptop
  GPU, wgpu Vulkan. These are functionality checks, not performance benchmarks.
- Host/API version: none observed; intended first target remains XCP-ng 8.3 LTS.

`./scripts/check.sh` passed formatting, Clippy with warnings denied, all **20 tests**
(7 core unit, 8 connection/protocol, 2 TLS, 3 desktop), debug workspace build, and three
headless screenshot/accessibility-tree exports. Artifacts are ignored under `artifacts/`.
The check script uses temporary local state and only fixture credentials.

The delivered local archive is `artifacts/xenadmin-rs-0.1.0-linux-x86_64.tar.gz`,
SHA-256 `897697d4c67d3e7d7dc4fa4a1942ce0f836390cd8ee9c72cca8b5ad5320bdbd2`.
It includes notices and declared license metadata for 376 packages in the host-platform
Cargo graph, including development dependencies; eight packages supply no separate notice
file, so their declarations and available READMEs are included. The archive is built on
this workstation and is not yet a clean-distribution portable release.

The final native demo run presented 60 frames with zero reported failed acquisitions or
skipped frames in the current Wayland desktop session. An X11 client run through the
local Xwayland display failed with Rune/wgpu `Surface::configure: Invalid surface` under
automatic GPU selection. Repeating with `WGPU_ADAPTER_NAME=NVIDIA` presented 30 frames with
zero reported failures or skips. The hybrid-GPU default-selection issue remains open.
These smoke runs do not establish real console input, clipboard, accessibility, or
standalone Xorg compatibility.

CI is configured for Ubuntu 24.04, local protocol tests, and Mesa software-Vulkan headless
renders. A workflow definition alone is not a passing CI result; consult the repository's
actual Actions runs for the current commit.

## Remaining work before a recovery release

- Designate a disposable 8.3 pool, credential reference and authorized test scope. First
  verify read-only login, API lineage/version, inventory and member redirects. Then verify
  actual console negotiation and the XO-unavailable power/console workflow.
- Qualify `vnc-rs` against QEMU console encodings, resize and cursor behavior, non-US layouts,
  modifier combinations, and QEMU extended keys. Extended-key negotiation is not implemented;
  use the planned contained libvncclient adapter if qualification requires it.
- Add console relocation/reopening after migration or reboot, wheel and middle-button input,
  and explicit clipboard controls. Current consoles close with their connection generation;
  the user can reopen them manually.
- Add matching-schema generated bindings, required non-event classes, and device relationships.
  The current bounded decoder covers the initial five event classes only.
- Add saved multiple profiles, keyring integration, same-pool connection deduplication,
  remembered-member failover, jitter, and automatic recovery from malformed event batches.
  The desktop currently manages one direct connection at a time.
- Add an operator-resolution flow for journal entries that remain unknown without a task
  reference. They currently remain visible and block conflicting mutations. Expand fault
  injection to journal I/O/corruption and cancellation/completion races.
- Qualify software Vulkan, clean installation, HiDPI, keyboard-only navigation, file dialogs,
  AT-SPI/Orca, and both real display protocols. Resolve automatic X11 GPU selection.
- Implement the planned metrics, VM creation/editing/devices/snapshots, migration, host/storage/
  network administration, and import/export milestones. None is claimed by this alpha.

The application requires reachable XAPI and console services. It cannot recover an
unavailable host toolstack or bypass host permissions.
