# GPUI migration, gate G3 (supported core): state on 2026-11-19

Gate G3 of [the migration plan](../GPUI-MIGRATION.md) ("Phase 3: supported core"), criterion by
criterion, after the cutover of the code. Each criterion is quoted word for word from the plan and is
one of: **met**, **partly met** or **not met**, with what shows it and what is missing. This report
supersedes [the report of 2026-11-14](2026-11-14-gpui-gate-g3.md), which described headless previews
that called no host and no longer exist.

**The gate is not passed.** Criterion 4 is partly met with one test row open; criterion 2 is partly
met, headless; criteria 1, 3 and 5 are not met. The plan made G3 "the recovery gate on the GPUI
build": that run has not taken place.

Terms as in [the G2 report](2026-11-19-gpui-gate-g2.md): a *test* runs on the Kit's headless test
platform; *live, headless* is the real shell and core against the lab without a window
([report](2026-11-19-gpui-live-headless.md), evidence directories under
`/var/lib/libvirt/images/xenadmin-rs-lab/evidence/gpui/`). Nothing of the GPUI front end has run in a
real window.

## Criteria

### 1. "The recovery gate from `README.md`, run with the packaged GPUI AppImage on an empty state directory: with XO shut down, locate the XO VM, start it and use its console."

**Not met.**

No AppImage of the GPUI front end has been built, and no packaged build of it has been run. (The
packaging script built an archive once on the development workstation at the cutover; it was not
installed or started.) The headless runs connected on an empty state directory, located guests,
started one and typed into its console, but with Xen Orchestra running, without a window and not
from a package, and the appliance's own console was not used.

It needs: `./scripts/package.sh --appimage` (or the CI build), then the gate as `README.md` states
it, in a real session, with the client's connections observed.

Interruption and refusal paths shown: a client closed in the middle of a shutdown, the guest halted

Missing, and named by the criterion or by the supported list of `docs/FEATURES.md`:

- a cancelled migration;
- "each refused review": the maintenance review refused for a stale set of guests and the host's own
  refusal of an evacuation, a reboot refused because the host is enabled, a storage move refused while
  a snapshot exists, a forced shutdown during a migration refused unless accepted, a revert that is
  refused;
- connection recovery through a lost host, a toolstack restart or a coordinator change, and a changed
  certificate: the rules for the lab on that day did not allow them. The core's own live scenarios
  cover them at the core's level;
- reboot, suspend, resume, the force actions and Start on Server; a batch that stops on a failure;
- restarting a host's toolstack, and rebooting or shutting a host down through maintenance;
  maintenance of the coordinator;
- a migration with its disks, and a halted VM's disks moved to another repository;
- snapshots with memory; the console in a separate window, fullscreen, the clipboard commands and
  typing the clipboard as keys;
- a saved password in the desktop keyring and connection at startup.

The live runs were made at commit `e2d4572`, and the tree has changed since. Merged after them: the
last round of fixes to the model and to the renderer (the branches `port/f1` and `port/f2`; 72 source
files of the two crates differ between `e2d4572` and `89d700c`, among them the Events history, the
rows of local actions, the search selection, the row menu of a grid and the reasons of disabled
controls),
and then the cutover, which renamed the crate and changed the front end in four more places (where a
group's key sits, a private text area's edit, the Down key after a click in a table with several
selected rows, the order of the Storage tab's row of actions; commit `60785ff`). The thirteen live
tests are ignored tests and were not run again on any later tree; the fixture tests and the scene
renders were. What the live run shows is therefore shown for `e2d4572`, and for today's tree only as
far as the fixture tests carry it.

And all of it was headless: "through the GPUI build" was the application inside a test process. It
needs the missing paths run, and the whole again in a real window (criterion 3 and the recovery gate
cover part of that).

### 3. "One driven desktop session (nested compositor, AT-SPI, physical key injection) covers connections, tables, search, console keyboard input and the host console."

**Not met.**

No driven session of the GPUI front end has been run. The harness of the earlier driven sessions
finds its elements in the accessibility tree of the Rune interface; its lookups have not been updated
for the new tree. Console keyboard input in such a session would be the first use of the Wayland
key-code path of [decision 0006](../decisions/0006-console-key-codes.md) with a console: that path
compiles in the client and has no test.

It needs: the harness's lookups rewritten for the new element tree (the tree of every scene is in
`artifacts/ui/*.json`), then the session.

### 4. "Every scene and interaction test of the supported areas is ported."

**Partly met.**

- Scenes: all 129 scenes of the old front end are registered and render
  ([ledger](../GPUI-MIGRATION-LEDGER.md), Scenes table; `python3 scripts/gpui_ledger_tables.py check`).
- Tests: the ledger gives each of the 371 tests of the old front end its disposition: 154 moved, 118
  ported, 94 split into a model test and a window test, 4 retired with a reason, 1 open. The open row
  belongs to a supported area (navigation and search):
  `search_clear_button_empties_the_search_and_restores_every_row`, of which the click on the
  navigation search box's own clear button is not asserted.
- Not done, and said in the ledger: the assertions of a successor were not compared with those of the
  test it succeeds; 5 ported rows have no window half although their name promised reachability at a
  window size; no test has a console stream (the canvas with real frames and keys was exercised only
  in the live headless run), and the Wayland key listener has no test.

It needs the one open row closed. The comparison of assertions is a review the operator may or may
not want.

### 5. "`./scripts/check.sh` still passes for the Rune build."

**Not met, and it can no longer be met.**

The Rune build was removed at the cutover (commit `71d9119`). No run of the whole script with both
front ends in the tree is recorded for the last commit before the cutover (`89d700c`): the engineers
of the last rounds ran its cargo steps one by one. From the cutover on, the script checks the GPUI
front end only, and criterion 1 of [gate G5](2026-11-19-gpui-gate-g5.md) takes this one's place.
