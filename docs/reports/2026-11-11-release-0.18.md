# 0.18.0, the first release

0.18.0 is the first published version of the client: a beta for XCP-ng 8.3, marked as a
pre-release. It is tag `v0.18.0` at commit `bdb79f3ffdb44f1c4c668f6602706c4389d8aa2c` on
the main branch, published on 2026-11-11 at
<https://github.com/z23/xenadmin-rs/releases/tag/v0.18.0>. The operator decided the label,
the branch and the publication that day.

What it supports and what in it is experimental is drawn in the
[feature scope](../FEATURES.md); what changed, what is known to be wrong and what was not
verified are in the [changelog](../../CHANGELOG.md), which is also the release's notes. The
[parity ledger](../PARITY-IMPLEMENTATION.md) remains the completion authority, and no
milestone is declared complete by this release.

## Since the 0.17 checkpoint

Thirty commits. They are the work the plan listed as the minimum for leaving alpha:

- The supported part was drawn and the rest marked experimental, in the documents and with
  a notice above every experimental dialog.
- Failure paths of the supported part were recorded on the lab: operations interrupted by a
  client restart, XO unreachable with its VM running, a session closed on the host with no
  outage, and a console lost while a key was held.
- Defects those runs and the operator's sessions on a real seat exposed were fixed: an exit
  from maintenance that the client's own journal refused, a removed directory user who
  stayed connected, a connection that reported itself ready with a stale inventory, charts
  that stopped after their first load, a password store that stayed locked, and the desktop
  defects listed in the changelog.
- Every core verification scenario gained a fixture test for its stated observation.
- Clipboard text can be typed into a console as key presses.
- The packages were installed on untouched Ubuntu and Arch images, and the client was
  checked under the X.Org server without Wayland.

## Verification

[CI for the commit](https://github.com/z23/xenadmin-rs/actions/runs/42957990942) passed
before the main branch was moved to it. The
[tag's workflow](https://github.com/z23/xenadmin-rs/actions/runs/42961198716) then repeated
the checks on the tagged commit and built the packages: formatting, Clippy with warnings
denied and 1,290 workspace tests (574 core unit with six native suites ignored, 354 direct
protocol, 349 Rune with one measurement ignored, five profile, four TLS and four probe
cases), the 46 vendored RFB tests, 29 lab tooling tests and 21 packaging tests, and the
headless scenes. The 93 live scenarios are ignored there by design; they run against the
lab.

The packages were checked while the release was still a draft, and it was published only
after that:

- Both were downloaded from the draft and matched their checksum files, on the workstation
  and again inside the virtual machine.
- On an untouched Ubuntu 24.04.5 cloud image with only the documented runtime packages
  added, the archive's installer put release `0.18.0-c3a46ca7c9e6b3fb` under `~/.local` and
  reported it active.
- The installed desktop rendered three scenes with the software Vulkan driver: the
  synthetic inventory, the console with a typing review pending, whose tree holds the new
  button, and a host administration dialog, whose tree holds the experimental notice. The
  AppImage, run by extraction, rendered the synthetic inventory to the same bytes as the
  installed build.
- The installed probe logged in read-only through a lab member with each endpoint pinned
  to its own certificate, the password given on standard input, and listed the lab pool
  with its two hosts.
- After publication the public release page answered and the public checksum file was the
  one checked.

The live evidence is in the [live qualification report](2026-11-09-lab-qualification.md),
all of it on XCP-ng 8.3.0 in the disposable lab and gathered from builds of the workspace,
not from these packages. The last live run before the tag was the typed-text scenario, on
the code that was released.

## What this does not show

- Nobody has used the released packages: the checks above were scripted, on one
  distribution, without a display.
- No login through the desktop window and no console were tried from the packages. Those
  paths were exercised from workspace builds of the same source.
- The Arch image was not started again for this build; it was checked with the CI build
  of an earlier commit ([clean-install report](2026-11-11-clean-install.md)).
- The packages are not signed. Their checksums detect damage and do not authenticate a
  download.
